# رحلاتي — Rahalati Travel Journal

الإصدار: **3.0.0**

تطبيق سفر Mobile-first مبني كـ PWA ويرتبط بـ Supabase للحسابات والمزامنة والصلاحيات.

## ما هو جاهز

- تسجيل دخول دائم بالإيميل أو اسم المستخدم.
- نظام مالك ومستخدمين؛ لوحة إدارة المستخدمين تظهر للمالك فقط.
- بيانات كل مستخدم معزولة بسياسات RLS.
- إنشاء الرحلات وحفظ المخطط والحجوزات والأماكن والمصروفات والشنطة والمستندات والملاحظات.
- نسخة احتياطية JSON قبل التحديث.
- نظام إصدارات: مرشح للمالك → اختبار → اعتماد → نشر للمستخدمين.
- زر Refresh في الشريط العلوي.
- PWA + Service Worker.
- قفل Pinch-to-Zoom ومنع Overscroll خارج التطبيق على الجوال.
- رقم الإصدار ظاهر في أسفل الصفحة.
- اقتراحات وجهات حسب الدولة/المدينة من Edge Function منفصل.

## بنية الملفات

- `index.html` واجهة التطبيق.
- `app.css` الهوية البصرية المتجاوبة.
- `app.js` منطق التطبيق والمزامنة.
- `config.js` إعدادات Supabase العامة ومعلومات الإصدار.
- `manifest.webmanifest` إعداد PWA.
- `sw.js` Service Worker وإدارة cache حسب الإصدار.
- `candidate/` مكان نسخة الاختبار الخاصة بالمالك في التحديثات المستقبلية.
- `supabase/schema.sql` مخطط جداول Rahalati وسياسات RLS.
- `supabase/functions/` مصادر Edge Functions المستخدمة.

## النشر على GitHub Pages

أنشئ مستودعًا عامًا أو خاصًا يدعم Pages، ثم ضع محتويات هذا المجلد في جذر المستودع على فرع `main`. فعّل GitHub Pages من إعدادات المستودع واجعل المصدر هو الفرع `main` والجذر `/`.

> لا تضع أي Service Role Key في GitHub أو داخل ملفات الواجهة. الواجهة تستخدم Publishable Key فقط، بينما العمليات الإدارية الحساسة تعمل داخل Supabase Edge Functions.

## دورة التحديثات المقترحة

1. جهّز الإصدار الجديد كنسخة كاملة داخل `candidate/` أو مسار اختبار منفصل.
2. من لوحة المالك في Rahalati أنشئ إصدارًا مرشحًا وحدد مسار النسخة التجريبية.
3. المالك وحده يرى شريط النسخة التجريبية ويفتحها للاختبار.
4. بعد الاختبار يضغط **تم الاختبار** ثم **اعتماد**.
5. عند نشر ملفات الإصدار على المسار العام يتم الضغط **نشر للمستخدمين**.
6. المستخدمون لا يرون الإصدار قبل النشر، وبعد النشر يظهر لهم إشعار مع خيارات: تحديث، نسخة احتياطية، أو لاحقًا.

**مهم:** حتى يتم ربط مستودع GitHub فعليًا والتحقق الآلي من ملفات المرشح، زر النشر يغيّر حالة الإصدار في Supabase ولا ينسخ ملفات `candidate/` إلى الجذر بنفسه. بعد إنشاء مستودع Rahalati يمكن إضافة التحقق/الترقية الآلية من GitHub كطبقة أخيرة.

## اقتراحات الوجهات والتقييمات

الدالة `rahalati-destination-suggestions` جاهزة لاستخدام Google Places لعرض:

- اسم المكان وتصنيفه.
- التقييم.
- عدد آراء المستخدمين.
- رابط المصدر/Google Maps.

لإظهار التقييمات الفعلية يجب إضافة Secret باسم `GOOGLE_PLACES_API_KEY` إلى بيئة Supabase Edge Functions. إذا لم يكن المفتاح موجودًا، تعمل الدالة تلقائيًا بوضع احتياطي عبر Wikivoyage، لكن بدون تقييمات وعدد آراء.

## Supabase

الجداول كلها تبدأ بـ `rahalati_` حتى تبقى معزولة عن التطبيقات الأخرى الموجودة في المشروع. ملفات SQL ومصادر الوظائف موجودة في مجلد `supabase/` كنسخة مرجعية للمشروع.
